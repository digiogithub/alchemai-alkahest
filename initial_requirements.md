# AlchemAI Alkahest

Este proyecto busca ser una plataforma de fácil uso para desplegar y utilizar modelos LLM y otros modelos de AI on-premise y en local.

En primer lugar quiero que tenga capacidad de comandos cli como el proyecto de Ollama, para hacer un pull de modelos, listar, borrar los modelos locales y ver si están en memoria, "ollama ps|ls|pull|..." pero quiero poder descargar modelos gguf tanto de ollama como de hugging face principalmente, y poder usar el apikey de hugging face para acelerar la descarga, opcionalmente. Quiero que sea compatible con los modelos que ya tengo cargados en ollama en mi instalación en local para poder cargarlos desde alkahest. Como ollama me gustaría que pueda instalarse como servicio que arranque automáticamente y que cargue los modelos on-demand cuando se pide por API, se carga el modelo, y pasado X minutos en el que no se usa, se descarga de memoria.

También quiero  tener la posibilidad de trabajar con diferentes engines o backends, dependiendo del modelo, pudiendo usar también las variantes de llama.cpp que permiten cargar los modelos ternarios de bonsai2 (funcionando en /www/Pips/llm/) como hace local.ai (clonado en `/www/MCP/Alchemai/Alkahest-refs/LocalAI`), vllm, modelos de visión, de audio, modelos de decisión exponiendo API tipo Jev que es soportado también por las últimas versiones de ollama (clonado en `/www/MCP/Alchemai/Alkahest-refs/ollama`).

El binario debe de estar desarrollado en Rust para buscar tener un ejecutable compacto y rápido. Debe de poder tener scripts de configuración para Windows, Linux y Mac (aunque principalmente voy a usarlo en linux), para poder descargar y/o compilar las versiones de llama.cpp adaptadas, a modo de recetas, y las librerías compiladas de nvidia-cuda en sus diferentes versiones, vulkan, amd, o cpu. Inicialmente el paquete podría venir únicamente con soporte CPU como fallback.

La llamada al cli, con el parámetro "desktop", como `alkahest desktop` debería de mostrar una interfaz de escritorio dependiendo de la plataforma para la que ha sido compilada, para Linux, Windows o MacOSX. La interfaz desktop debe de estar hecha con GPUI como ya he hecho bitacora `/www/Bitacora/bitacora` o pando-assistant `/www/MCP/Pando/pando-assistant`. La interfaz desktop tiene que permitirme pasarle un modelo de hf, sea normal para vllm o en gguf, tener buscador de modelos de hf (hugging face), poder descargarlos en una carpeta, borrarlos, editar las optimizaciones (kv,... debe de setear los valores recomendados que vienen en la ficha del modelo de hf, también poder configurar la context window). También poder buscar y descargar del catálogo de ollama, pudiendo configurar también la template, activar tools, y la context window.
La interfaz desktop además de poder gestionar los modelos debe de poder configurar apikeys para acceso externo (fuera de localhost), y ver los modelos cargados (si CPU o GPU), ver el consumo de RAM o VRAM, y ver si se está accediendo a él en ese momento (cantidad de requests encoladas al modelo). Se debe de poder distinguir el tipo de modelo: de embeddings, de generación de imágenes, de vídeo, de decisión, gguf, válido para vllm, etc... Puedo descargar o parar un modelo concreto quitando el proceso de memoria.

En una primera versión no quiero todas las opciones que tiene local.ai de tener un chat web ni interfaz web, sólo un servidor API unificado con todas las características y todos los modelos cargados, un API OpenAI compatible como ollama y Jev compatible.
