Root cause (2026-10-17, ~16:00 CEST, Saturday): not an Alkahest or rustls bug. The ISP blocks the Cloudflare IPs serving the R2 blob host.

- DNS is correct: local resolver and 1.1.1.1 both return 172.64.66.1 and 172.64.190.1 for `<id>.r2.cloudflarestorage.com`.
- Both IPs, with any SNI (also `example.com`), present a self-signed certificate `CN=core1.netops.test, O=Widgits Pty Ltd, OU=Packetland` with `CA:TRUE` (SHA-256 F6:A3:26:1B:…:41:8D). That is exactly `CaUsedAsEndEntity` for rustls; curl/OpenSSL reports `self-signed certificate` too.
- Plain HTTP to 172.64.66.1 returns the block notice: "El acceso a la presente dirección IP ha sido bloqueado en cumplimiento de lo dispuesto en la Sentencia de 18 de diciembre de 2024, dictada por el Juzgado de lo Mercantil nº 6 de Barcelona … instado por la Liga Nacional de Fútbol Profesional y por Telefónica Audiovisual Digital" (court-ordered LaLiga IP blocking in Spain, applied on match days).
- Route is plain: host → 192.168.1.1 → ISP; no local proxy, no proxy env, no overlapping route. Other Cloudflare IPs (registry.ollama.ai 104.18.16.170, r2.dev 104.18.50.34) serve valid certificates, which is why the manifest fetch works and only the blob redirect fails. IPv6 to the R2 host times out.

Workarounds: retry after the block is lifted, use a VPN / Tailscale exit node, or pull from Hugging Face. Rejecting the certificate is correct behaviour and must stay.

Possible improvement (needs a decision): when a TLS verification error happens, name the host and the presented certificate's subject/issuer in the error, and hint that the network may be intercepting or blocking (e.g. "the certificate is self-signed CN=core1.netops.test: a proxy or network block is in the way"), instead of the bare rustls error after 7 retries; also do not retry certificate errors 7 times, since they are not transient.
