Implemented in commit c6f9d5e. `authenticate` middleware: client = socket peer (`ConnectInfo`, IPv4-mapped canonicalised), `X-Forwarded-For` only from `auth.trusted_proxies`; an untrusted loopback peer sending forwarding headers is treated as remote. Loopback needs no key unless `auth.require_on_loopback`; remote needs `Authorization: Bearer` or `x-api-key`; admin scope for `/alkahest/*`, `/api/pull|push|create|copy|delete`, blob uploads (403 otherwise); disabled families (`[server.endpoints]`) 404; CORS only for `server.cors_origins`. Dialect errors via the `ErrorRenderer` hook (default already Ollama/OpenAI/Anthropic shaped) for ALK-US-0038. `check_exposure` + `serve --allow-unauthenticated`: refuses a network bind without keys. `RequestContext` in request extensions for handlers (model allowlist via `Principal::allows_model`). Tests: `crates/alkahest-api/tests/auth.rs` (scenarios missing_key, inference_key, disabled_family, spoofed headers, IPv6, revoked, timing-safe same 401), `crates/alkahest/tests/serve.rs#startup_refusal_*`. Change record with security checklist: docs/development/changes/2026-10-17-auth-middleware-exposure.md. Security-tagged: needs product owner review.
