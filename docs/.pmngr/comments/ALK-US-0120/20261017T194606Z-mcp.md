Implemented on branch `alk-us-0120`, commit 4e9e5e3 (not merged).

- R13 rewritten in ALK-SP-0011 to match the product owner decision: catalog models are `alkahest/<namespace>/<model>[:<tag>]` (pseudo-host, parsed like `hf.co`), no `catalog:` prefix, `--catalog <name>` on pull/search, the default tag is stored as the concrete first variant. R7 now allows loopback-only plain http model URLs (for local mirrors and tests) and needs `size` > 0.
- `alkahest pull alkahest/...` resolves the entry through the layered snapshots, downloads with alkahest-fetch (mirrors in order, sha256 and size verified, host token only where `auth` says so), and writes a manifest with model/projector layers, params, a Go template, source and config (origin) layers. Engine, template and params become recommended defaults. A failed pull leaves no manifest and no blob.
- `alkahest search --source catalog|all [--catalog]` lists catalog rows first, with size, quant, licence and tags. New admin endpoint `GET /alkahest/v1/catalog/search`, and `POST /alkahest/v1/pulls` accepts `catalog`.
- xtask catalog-check now uses the shared `alkahest_catalog::ModelEntry` schema.
- Verification: fmt, clippy -D warnings, nextest 1310 passed / 1 skipped, check-deps, catalog-check, docs-cli --check and the headless build all pass. cargo deny advisories still fail on the existing RUSTSEC-2026-0370/0371.
- Change record: docs/development/changes/2026-10-17-catalog-models.md.

Open points: safetensors catalog variants cannot be pulled yet. A Go `template_text` does not override the GGUF template. The `catalog:` wording in the ALK-SP-0011 Scope paragraph has not been updated.
