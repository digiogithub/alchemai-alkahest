Fixed in commit ac2368c (branch worktree-agent-a8f56e8265702f0e6).

- Windows: one job object per engine with JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE; the server holds the only handle, so a killed server takes the engine tree with it.
- macOS (and other non-Linux Unix): a per-engine `/bin/sh` watchdog in its own process group checks once a second that its parent is still the server (`ps -o ppid=`, robust to zombies and pid reuse) and that the engine lives; then SIGTERM to the engine group, SIGKILL after 5 s. Killed and reaped by the supervisor with the engine. `ALKAHEST_ENGINE_WATCHDOG=1` forces it on Linux (used by the tests).
- Tests: `crates/alkahest-engine/tests/orphans.rs#engine_dies_with_the_server_through_the_watchdog` (re-exec SIGKILL scenario with the watchdog), `engine_dies_when_the_server_is_sigkilled` now on every Unix, unit tests `orphan::tests::watchdog_kills_the_engine_group_when_the_server_dies`, `watchdog_exits_when_the_engine_is_gone`. macOS clippy clean; not run on a Mac.
