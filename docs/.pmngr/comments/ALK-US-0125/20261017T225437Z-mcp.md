Second cause, found 2026-10-18: the product owner uses Pando's "OpenAI compatible" provider, which requests `TrimRight(baseURL, "/") + "/models"`. With a base URL without `/v1` that is `/models`, a 404 on Alkahest. `normalize_path` now also prefixes `/v1` when the first segment is an OpenAI/Anthropic resource (`models`, `chat`, `completions`, `embeddings`, `audio`, `images`, `rerank`, `responses`, `messages`), as llama-server and LocalAI accept. Test `crates/alkahest-api/tests/ollama.rs#openai_routes_answer_without_the_v1_prefix`; 1361 tests pass.
