## What changed

### `alkahest-api`: `admin` module (was `admin.rs`)

- `admin/mod.rs`: `ROUTES` (`RouteDoc { method, path, tag, summary }`) generated by one
  macro together with the handler table, so `routes()` and `openapi_document()` cannot
  drift; `GET /alkahest/v1/openapi.json` (OpenAPI 3.1, hand-built from the table: no utoipa
  derive work was needed). `parse_body` (empty body = default, unknown fields refused per
  type), `reply` (admin dialect errors).
- `admin/context.rs`: `AdminContext` (config, resolved paths, the config file network
  settings are saved to, `JobManager`, optional `PullRunner` and `EngineManager`, HF token
  store, environment lookup, Ollama library URL, cached `SystemInfo`, saved network
  settings) with `AdminContextBuilder`; registered as `Arc<AdminContext>` service.
- `admin/jobs.rs`: `JobManager` (`start` dedups a running job of the same kind and target,
  `list`, `get`, `cancel`, `remove` finished, `subscribe`), `JobHandle` (`phase`,
  `progress`, `cancel_token`), `Job`, `JobKind::{Pull, EngineInstall}`,
  `JobState::{Running, Completed, Failed, Cancelled}`. Progress events throttled to one per
  200 ms per job; state and phase changes always published; 50 finished jobs kept.
- `admin/runtime.rs`: the existing `ps`, `unload`, `/metrics`; `events` now merges the
  scheduler `status` events with `job` events (works with either source).
- `admin/models.rs`: catalog list (every `ModelSummary` field plus `runtime` of loaded
  models, store paths/counts/size, Ollama `read_only`), detail (template, system, licence,
  parameters, source info, shadows), delete (unload first; Ollama store 403), copy, settings
  GET/PUT/DELETE (overlay, recommended layer, effective values, `origins` per field; a model
  may be configured before it is pulled; value checks for sampling ranges and cache types),
  recommended layer, memory estimate (GGUF, from the effective settings plus query
  overrides, with `fits`).
- `admin/pulls.rs`: `PullRunner` trait (implemented by `PullService`), pull jobs
  (`quant` becomes the HF selector; refused for Ollama names), job routes.
- `admin/discover.rs`: HF search/model/files proxies (`gguf_variants` with the pull
  reference per quant, projectors, safetensors size), HF token status/set/delete (keyring),
  Ollama library search. Repo ids validated (`org/name`), HF auth errors are 502 not 401.
- `admin/engines.rs`: `EngineManager` trait and `RecipeEngineManager` (recipe catalog +
  engines dir, as `alkahest engines`): list, `check` (400/404 before a job starts), install
  job with byte progress, remove.
- `admin/keys.rs`: list (usage counters from the live `UsageTracker`), create (secret once,
  `Cache-Control: no-store`), revoke.
- `admin/settings.rs`: `NetworkSettings`; GET running/saved/`restart_required`/warnings;
  PUT partial patch written with `toml_edit` (comments and other keys preserved, standard
  tables, result must load, temp + rename).
- `admin/system.rs`: info (version, uptime, bind, paths, store counts, scheduler limits,
  hardware without CPU flags, accelerators, HF endpoint and token presence), engine log list
  and tail, server log tail.
- `audit.rs`: `UsageTracker::snapshot`.
- Dependencies: `alkahest-recipes`, `alkahest-sysinfo`, `alkahest-gguf` (now normal),
  `toml_edit = "=0.25.17"` (new workspace pin, already in the lock through `toml`; MIT/Apache).

### Binary

`alkahest serve` keeps the detected `SystemInfo`, builds a `RecipeEngineManager` and the
`AdminContext` (config file = `--config` file when given, else the user config file) and
registers it with the `UsageTracker`.

### `fix(engine)`: offload follows the installed build

`EngineInstall::runs_on(wanted)`: a `cpu` build runs on the CPU backend unless the platform
is Metal (the macOS archives labelled `cpu` carry Metal); unlabelled builds keep the
platform accelerator. `LlamaCppEngine::prepare` drops `-ngl` for such builds;
`CatalogBackend::resolve_blocking` sets the request accelerator from the plan so the
estimator charges RAM, not VRAM. Found in the vision tests (CUDA host, CPU build,
`-ngl 999`). Tests `tests/llama_cpp.rs#cpu_only_build_never_offloads`,
`#runs_on_follows_the_build_variant`.

## Security checklist

| Threat | Mitigation | Proof |
|---|---|---|
| Remote caller administers the server | whole `/alkahest/` prefix requires the admin scope (middleware, not handlers) | `tests/admin_api.rs#admin_routes_need_the_admin_scope_remotely_and_nothing_on_loopback` (401 no key, 403 inference key, 200 admin key, loopback open) |
| API key secret leaks | shown only in the create response, `Cache-Control: no-store`; listing has no salt/hash/secret; client `CreatedKey` Debug redacted | `create_key_shows_the_secret_once_and_listing_never_does`, client `keys_network_and_errors` |
| HF token leaks | accepted by PUT, never returned or logged; stored in the keyring | `hf_token_is_stored_never_returned` |
| Accidental unauthenticated network exposure | PUT refuses non-loopback + no key checks without `confirm_unauthenticated`; startup check still applies; warnings for no key / plain HTTP | `network_settings_are_saved_for_the_next_start`, `settings::tests::unsafe_exposure_needs_confirmation` |
| Config file corrupted | edit with `toml_edit`, result must parse and validate, temp + rename | `writing_keeps_comments_and_other_keys`, `writing_creates_a_missing_file` |
| Path traversal in logs | names matched against the directory listing after mapping to the scheduler's file stem | `engine_log_tails_and_names_cannot_escape`, `names_cannot_escape_the_log_directory` |
| Request smuggling into HF URLs | repo ids validated `org/name` | `discover::tests::repo_ids_are_checked` |
| Ollama store written | delete goes through `Catalog::remove` (403) | `delete_refuses_ollama_models_and_copy_then_delete_works` |
| Event stream flooding | job progress throttled, broadcast lag tolerated | `jobs::tests::byte_progress_is_throttled` |
| Large log reads | tail reads at most 1 MiB, at most 5000 lines | `system::tests::tail_returns_the_last_lines` |

Open points for product owner review: the HF token routes write the server user's keyring
(same store as `alkahest hf login`); network settings are not applied live (restart flag);
engine removal does not check whether a loaded model uses that build.
