# llama.cpp recipe and official catalog moved to b11970 (LFM3 support)

Date: 2026-10-28. Related: [[ALK-SP-0003]], [[ALK-SP-0011]], [[2026-10-28-desktop-saved-connections]].
Plan: [[plan/alkahest-v1-plan]].

## Why

`hf.co/mohommed/LFM3-1.7B-Frontier-SmartAgent-GGUF:Q8_0` (GGUF `general.architecture = lfm3`)
failed to load: llama-server `b11669` exits with `unknown model architecture: 'lfm3'`. LFM3
support landed upstream in ggml-org/llama.cpp PR #31252 (merged 2026-10-27, commit 19cce69); the
first release tag containing it is b11938 (GitHub compare API: b11937 behind, b11938 identical).
The pin moves to b11970, the latest tag at the time.

The inbox items ALK-US-0145 (pin bump) and ALK-US-0146 (recommended context = trained context)
were rejected by the product owner: the engine comes from the catalog and the context length is
set per model in the model settings.

## What changed

- `catalog/engines/llama-cpp.toml` (source of truth) and `recipes/llama-cpp.toml` (synced with
  `cargo xtask catalog-index --sync-recipes`, which copies catalog to recipes): every URL, `rev`,
  `sha256` and `size` for b11970, taken from the `digest` and `size` fields of the GitHub
  releases API (25 assets, all variants present). `catalog/index.toml` regenerated.
- Test fixtures that pair with the built-in recipe moved to b11970:
  `crates/alkahest-recipes/tests/recipes.rs`, `crates/alkahest/tests/engines.rs`,
  `crates/alkahest-api/tests/catalogs.rs`, and the shared fixture catalog
  `crates/alkahest-recipes/tests/fixtures/catalog` (index regenerated).

## Verification

- `cargo xtask catalog-check --net`: OK, network checked (9 engine files, 4 model files).
- `cargo nextest run --workspace --locked`: 1508 passed, 1 skipped.
- `cargo fmt --all --check`, `cargo clippy --workspace --all-targets --locked -- -D warnings`: clean.

Note for catalog authors: edit `catalog/engines/`, not `recipes/`; `--sync-recipes` overwrites
`recipes/` with the catalog copy.
