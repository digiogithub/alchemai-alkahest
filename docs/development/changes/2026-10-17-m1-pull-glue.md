# M1 pull glue: shared pull crate, persisted recommended defaults, bandwidth cap

Refs: [[ALK-US-0019]], [[ALK-T-0073]], [[ALK-SP-0002]], [[plan/alkahest-v1-plan]]

## What

- New crate `alkahest-pull` (deps: `alkahest-fetch`, `alkahest-store`): `Transfer`,
  `BlobSpec`, `PullEvent`, `PlannedBlob`, `PullProgress`, `TransferError`, moved verbatim from
  `alkahest-ollama::transfer`. `alkahest-hf` no longer depends on `alkahest-ollama`;
  `alkahest-ollama` re-exports the types so existing callers compile.
- `alkahest_hf::pull::pull_hf` takes `overlays: Option<&ModelOverlays>`; after the manifest is
  written the recommended parameters are persisted with `ModelOverlays::set_recommended_json`
  (ALK-T-0073). Failure is only logged. The manifest layer is kept so the advice travels with
  a copied model. Ollama pulls need nothing.
- `alkahest-core`: new `pull.rs` with `PullConfig { max_bytes_per_sec }`, field `Config::pull`
  (`[pull]` section, `deny_unknown_fields` kept), env `ALKAHEST_PULL_MAX_BPS` (0 = unlimited).
  `alkahest pull` feeds it into `FetchConfig::max_bytes_per_sec`.
- `cargo machete` clean (unused `alkahest-core` removed from `alkahest-ollama`).

## Verification

`scripts/ci-local.sh` passes (fmt, clippy -D warnings, nextest, deny, check-deps, headless
build, typos). New tests: `recommended_params_are_persisted_in_the_model_overlay_directory`,
`pull_bandwidth_cap_comes_from_the_environment`, `zero_and_absent_mean_unlimited`.
