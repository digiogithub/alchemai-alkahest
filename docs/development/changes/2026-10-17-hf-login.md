# `alkahest hf login|logout|whoami`

Implements [[ALK-T-0060]] (story [[ALK-US-0018]], [[ALK-SP-0002]].R3). Plan: [[plan/alkahest-v1-plan]].

## What

- `alkahest-hf`: `HfClient::whoami()` (`GET /api/whoami-v2`) and `WhoAmI` (name, fullname,
  type, orgs, token name and role).
- `alkahest` bin: `hf_cmd.rs` and `HfAction` in `cli.rs`.
  - `login [--no-verify]`: reads the token with a no-echo prompt (`rpassword`, pinned `=7.4.0`,
    Apache-2.0) on a terminal, or one line from stdin when piped; verifies it with `whoami`
    unless `--no-verify`; stores it with `KeyringStore`. A rejected token is not stored.
  - `logout`: deletes the keyring entry; notes a lingering `HF_TOKEN`.
  - `whoami [--json]`: uses `HF_TOKEN` first, else the keyring; prints account, orgs, token
    role and which source is in effect. Exit 1 when no token is available.
  - The token is never printed, logged or accepted as an argument.

## Verification

wiremock tests in `hf_cmd.rs` with an in-memory `TokenStore`: login stores and does not echo,
rejected token stores nothing, whoami keyring vs `HF_TOKEN` precedence, logout. The real keyring
is not touched by tests.
